# C guest conformance fixture

`blob.c` is a maintained Component Model ownership/ABI fixture, compiled with
C bindings generated by `wit-bindgen` 0.60.0 from authoritative LSF WIT. It is
separate from the external C client's callback interface in `../c`.

The pinned Zig 0.16.0 compiler uses `wasm32-wasi`, `-O2`, reactor mode and a
64 KiB stack. Its bundled libc supplies allocation; component construction
rejects unresolved WASI imports, so this profile grants no ambient WASI access.
Generated sources and binaries stay in the selected build directory.

The fixture owns one heap frame per canonical task. Input/result storage lives
through pending imports; callbacks handle progress, completion and cancellation.
It detaches and retires subtasks, drops owned chunk resources, frees result
records and clears task context. Primitive blob handles remain owned by the
activation until explicit close or host cleanup. There is no global provider
state or hidden worker.

Real runtime tests cover close, abandoned handles/chunks, use after close,
repeated chunk materialization, a handle from a previous activation,
cancellation while the provider is queued, and fresh invocation after cleanup.
The [guest SDK reference](../../docs/component-development/guest-sdk.md) gives
the single build/test command sequence and signed-package boundary. This is a
conformance fixture, not a claim of a general ergonomic C guest SDK.
