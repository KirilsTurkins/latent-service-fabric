# Call-graph fusion semantic evaluation

This is a proposed bounded experiment. No optimizer, composition harness or
conformance run is delivered by this document. Use the
[source and semantic baseline](README.md) and the
[literature/tooling review](upstream-review.md) before interpreting results.

## Initial candidate and comparison rule

Use the supported Linux x86_64 Wasmtime environment with two small components,
then a three-member serial chain. Select exact same-tenant publications and
bindings; use the same canonical service import, value codec, audit policy and
resource ceilings as the ordinary path. Preserve separate logical activations
and cells for the first joint-preparation experiment. Do not enable fusion for
production manifests or alter Angular SSR eligibility.

Freeze the candidate's semantics before benchmarking. Compare logical call
events and effects, not merely root output: selected target, derived principal,
start acceptance/rejection, parent/root relationships, payload/outcome contract,
budget owner, deadline, audit and physical retirement. Normalize fresh IDs and
controlled timing without erasing tenant or publication distinctions. Record
the actual interleaving for concurrent tests; faster execution may change which
race wins, so test defined start-fence orderings with explicit barriers.

For level A, preserve current capacity policy and compare the same controlled
admission conditions. For a later level B/C candidate, explicitly identify any
changed resource/metering/admission semantics. A path that accepts more work by
ignoring child reservations is not a faster equivalent implementation.

No shadow execution of business calls is permitted to check equivalence: it
could duplicate effects. Use independent controlled fixture runs and a logical
trace oracle. An unrestricted monolith may be a reference but has a different
contract. Bound all experiment resources and record source/artifact identities;
large load, profiling and soak campaigns require separate scope.

## Derived artifact identity and current authority

Separate immutable specialization inputs from live invocation owners.

| Reusable identity must bind | Retained per logical invocation, not cached in the artifact |
| --- | --- |
| Ordered/directed graph, call-site identity and repeated edge occurrences; every member's tenant, publication, release, deployment revision and component digest. | Fresh activation, parent/root/trace IDs and the actual derived service principal. |
| Exact imported/exported contract/function types, function kind, host ABI, selected binding/route and provider identities; adapter bytes and value-codec rules. | Actual payload/outcome buffers, resource handles, credentials and capability sessions. |
| Policy snapshots/generations and restrictions used for specialization, with explicit dependencies and validity predicates. Observed graph membership is not authority. | Current eligibility and grant checks at each logical start, using the ordinary owners and accepted cutover rules. |
| Runtime/compiler/target/security profile, composition tool and generated bytes; accounting/metering model and any ceilings compiled into the artifact. | The original ledger instances, remaining grants, finite reservations, monotonic deadlines and live cancellation tree. |

Every input affecting generated behavior must be represented; do not omit policy
or accounting assumptions to improve cache hits. Conversely, do not embed a live
request's identity or ledger in reusable code. If specializing on a request
limit, include that limit in the identity and charge the resulting variants.

Revalidate the selected target at the actual logical boundary. For example,
revoking B after A starts but before B's start fence must not be bypassed by
cached B code. Preserve the distinction between not-yet-started and already
accepted work. A miss must not silently select another revision, publication or
route when the original contract would reject it.

Use bounded currentness/start actions; do not hold global route or policy read
guards across guest execution, compilation or I/O to freeze an entire graph.
Retain active immutable code pins until their borrowers retire, while stale
entries deny future starts. Dependency invalidation and memory reclamation are
different operations.

## Fallback without replay

Initially choose ordinary or specialized execution before the root starts.
If preparation, selection or verification fails, release provisional owners and
use the ordinary path only after independent current checks. Do not reuse a
failed candidate's admission as permission for a different target.

Once any relevant work is accepted, preserve ordinary failure handling. Do not
restart the root, replay an accepted child, or retry an uncertain audit outcome
to hide an optimization failure. Idempotency keys in current local calls are
correlation, not durable deduplication. A future per-edge fallback would require
proof that that edge has not started and an explicit ownership transfer; it is
outside the first prototype. Invalidation can disable future candidate uses
without replaying the current invocation.

## Bounded discovery, compilation and cache ownership

Observe actual trusted broker call edges and phase timings in a finite,
tenant-scoped window. Retain identifiers, sizes and aggregate timings, not
payloads, credentials, guest heaps or provider connections. Observed absence of
an edge is not proof that the application cannot take it. Unseen branches must
retain supported ordinary behavior or fail under an explicitly scoped research
model; they cannot be optimized away.

Declare hard ceilings on graph nodes/edges/depth, candidate count, observations,
compilation jobs, queued work, build time, input/output bytes, retained code,
dependency-index fan-out and active pins. Charge abandoned/invalidated builds
and duplicate member/composite images. Reuse existing bounded preparation
workers where appropriate; no optimizer worker or initialized guest per service.
Code prefetch must use its authorized catalog owner and preparation allowance,
and cannot execute guest initialization or capabilities speculatively.

Start with bounded candidate enumeration rather than a claim of global
optimality. Later policies need minimum useful reuse, hysteresis and backoff to
avoid compiling every transient graph/release combination. Policy/release churn
must be measured as a cost. Cache pressure may cause an ordinary miss; it must
never drop guards, evict still-borrowed code or grant stale execution.

## Semantic comparison matrix

Each case needs the ordinary control, candidate, deliberate violation and an
independent observation of effects, owners and retirement. Reuse existing test
fixtures where possible, but their current results qualify only the ordinary
path. Do not relabel test registration or a composed binary as executed evidence.

| Case | Required observation |
| --- | --- |
| Repeated B call and initialization | A calls B twice; each logical B begins with fresh globals, memory and handles. Constructor effects occur only after that child's actual admission. No retained B state or speculative initialization on an untaken branch. |
| Member-specific authority | A may invoke B; only B may use a secret/provider. A cannot exercise B's grant, impersonate B through metadata or reuse B's handle. Test equal tenant with different principals/policies. |
| Handled child failure | Parent successfully handles a child admission/load/platform failure. Preserve declared errors, platform failures, traps and nested result data as distinct outcomes; no root trap substituted for a catchable child failure. |
| Opaque values and adapters | Compare payload/result bytes, media type and metadata; malformed, oversized, nested, numeric and top-level error cases keep codec validation and bounds. Copy savings must be measured rather than inferred from a typed connection. |
| Warm code with stale authority | Change publication eligibility, binding, provider or policy before B's start. Held plans/composites cannot authorize a new B; an already accepted start follows the normal fence rule. |
| Required audit pressure | Fill the required journal before child admission. B must not start, run a constructor or emit effects; acceptance and uncertain terminal writes cannot trigger automatic retry. |
| Fuel and descendant conservation | Preserve accepted child-call charges, delegated limits and original ledger instances. Guest instructions are charged once; native fuel checkpoints/resumption cannot re-spend reserved fuel. Test concurrent reservations and exhaustion. |
| Cells, saturation and fairness | With a waiting parent holding its cell, the initial candidate retains ordinary prompt child rejection. Any fewer-cell design needs a declared policy and competing-work fairness evidence. Report rejection rate and wait time, not just successful latency. |
| Deadlines and cancellation | Original absolute monotonic deadlines survive preparation, child waits and resumption. Cancellation reaches accepted descendants; late completion cannot affect another activation. A client timeout does not refund live work. |
| Abandonment and cleanup | Drop the parent waiter during an accepted child. Node-owned child/result cleanup completes; retained output remains charged through lowering/Store destruction. Missing proof causes quarantine without a false refund. |
| Branches, recursion and invalidation | Previously unseen targets, repeated edges, attempted cycles and graph changes cannot bypass current target/depth checks. Stale code remains pinned for active borrowers but cannot start new logical work. |
| Strict transactions and other profiles | A forbidden immediate child effect remains forbidden after optimization. Exclude transaction graphs and Angular SSR; fusion does not merge command identity, state namespace, commit or recovery boundaries. |
| Optimizer/resource failure | Exhaust compilation, metadata/index and image budgets; cancel builds and evict unused entries. No leak, unbounded job growth, partial artifact admission or replay of accepted work. |

## Measurement and promotion decision

Use the [benchmark protocol](../../benchmarks/fusion/README.md) to distinguish
ordinary calls, joint preparation and actual composition. Freeze semantic
acceptance before optimizing; report regressions and unsuccessful attempts.
Do not weaken audit, currentness, resource controls or cleanup to produce a gain.

A promotion ADR must state the exact optimization level, supported profiles and
value surface, immutable inputs, currentness/start fences, failure/admission and
metering semantics, cache/build bounds, maintenance owner, disable path and
conformance evidence. Changes to child Store/cell allocation or strict-command
effects need explicit decisions, not an eligibility flag. Preserve an independently
checked ordinary path without replaying in-flight work.

Proceed only if equivalent-workload measurements show a worthwhile benefit
after guard, compilation and churn costs. Deferring fusion because the remaining
cost is already small, or because preserving failure/freshness requires most of
the original machinery, is a valid research result. Retain raw evidence with its
source identities; later documentation cannot turn an unexecuted proposal or an
earlier component artifact into qualification.
