# Uninstalled PCI registration and uevent consumers

This grouped source prepares the actual Linux 6.12.113 PCI core, capability,
registration, kernfs/IDR and uevent paths. The authenticated derivation retains
ordinary allocator and callback bodies and adds private consumers of the
original NodeFixed bank. No consumer is installed. No kernel, driver, RX/TX,
physical shared-workqueue or final provider-teardown qualification follows from
source derivation or the supplemental serialized C controls.

The bank remains 512 KiB, with the original 192 KiB infrastructure tail, 256
records and 64 owner slots. The TCP and DNS allowances remain 96 and 64 KiB.
The existing separate 1 MiB bootstrap ceiling includes that same bank and
metadata; it does not add another bank. The 64 KiB event-head shape bound is
inside the infrastructure tail and is neither a DNS owner nor an extra quota.
Returned records and bump space are not reused within the retained generation.

Root event allocation requires the actual PCI birth and the exact current
constructor task, or the actual core-cleanup task while its callback is
executing. The task borrow is revoked before external return, validation
failure or cleanup scheduling. A failed constructor revoke poisons and retains
the original ownership state while still releasing the known-held factory
mutex; it does not call firmware constructor leave or invent a new borrow.

The real kobject_uevent_env continuation retains its action/state updates,
filter, subsystem name, device uevent callback, sequence number and broadcast.
The private environment and complete object path are admitted before storage
allocation in the original bank. Ancestor count, component length and complete
path length are bounded before the second path-copy pass. A changed path is a
closed failure, without another allocation or retry.

The private event supports the actual PCI device type and PCI bus callback,
without class, device-node, DT or child-namespace callbacks. Changed callback
identities, usermode helpers, caller-provided extra environment, synthetic
events, rename/move and sysfs uevent-show are Unsupported before the unclosed
callback or allocation. This restriction does not substitute successful stubs
for mandatory callbacks. The supported real callbacks still execute, and their
errors propagate.

Actual event SKB headers and shared heads retain the original PCI generation.
The maintained __skb_clone and dataref/users rules remain in use. Linear
geometry and the actual admitted head span are checked before shared-info
access. Copy, partial copy, expansion and final header/head routing use the
same original backing. Fragment, frag-list, zero-copy and fclone shapes are
Unsupported for this private event path. A shared head returns only at the
maintained last-dataref branch; its SKB header has its own actual final return.

An already-live event SKB may create a real descendant after descriptor close,
while its same-generation PCI parent remains live and the bank is retained.
Close does not turn a normal callback into a new root allocation authority.
Only the actual core-cleanup task may emit its required remove event during
that callback extent. Invalid, foreign or stale births poison and retain their
original backing instead of falling through to a heap allocator.

The real socket security hook dispatch remains mandatory. Private event
delivery rejects configured cgroup BPF, an attached socket filter or an
unknown active receive LSM before the corresponding unclosed call. The actual
SELinux receive hook's original netlink-family behavior is unchanged. A socket
filter is checked inside its original RCU extent, and every private refusal
releases that read-side extent. Ordinary recipient selection, queues, rmem
accounting, socket ownership/destructors and notifications are unchanged.

The all-net tap fence is necessary because the original multicast path permits
cross-namespace recipients using LISTEN_ALL_NSID, a peer namespace ID and the
receiver file's capability. Initial-user-namespace membership alone cannot
prove absence. With this selected, uninstalled profile, a pending or live
netlink tap blocks private bank acquisition, and private bank retention blocks
new taps in every possible receiver network namespace. The actual tap marker
and count are admitted before list publication and retired only after a
successful unlink and synchronize_net. Neither callbacks, allocation nor an
RCU wait run under this short pool-lock fence. Ordinary delivery is preserved.

Still required before installation are complete registration producer and
recipient callback closure, actual platform/bootstrap admission, configured
security and firmware behavior, shared IDR-tree/provider drain, physical
workqueue and deferred-return ownership, PCI setup/DMA/device initialization,
RX/TX/route/neighbour/page producers, and the sealed maintained kernel build,
layout/BTF, final-free, link/boot/install and bounded conformance proof. The
source has no completed backing-free path: close/quarantine retains the bank
and tap fence. Empty records, pointer disappearance, timeout or an empty socket
listing cannot establish physical retirement or enable the profile.
