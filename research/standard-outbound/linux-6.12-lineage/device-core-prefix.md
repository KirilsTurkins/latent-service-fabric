# Original driver-core metadata and final-tail ownership (uninstalled)

This finite source prerequisite layers over the maintained cached-ACPI prefix.
Normal factory selection remains `NULL`; it is not complete PCI registration,
an installed kernel, physical device/workqueue proof or production enablement.
The original TCP 96 KiB/DNS 64 KiB, 64 owners, 256 records, 512 KiB backing and
192 KiB infrastructure tail are unchanged.

Actual `device_private_init` normally allocates `struct device_private`. There
are two distinct original frees: `device_add`'s `name_error` and final
`device_release`. The latter runs the PCI release callback before freeing its
cached metadata pointer. The enclosing `kobject_cleanup` subsequently frees the
cached name and puts its parent. A PCI callback alone therefore cannot establish
that all original core cleanup has returned.

Successful selected setup already owns the prepaid firmware descriptor, even
when no companion exists. Before `pci_device_add`/`device_initialize`, the source
marks that existing descriptor as requiring a complete core tail. It does not
allocate another tail descriptor or queue. The extra finite fields are included
in its actual `sizeof` admission before lookup, as all original descriptor bytes.
Unknown/repeated initialization and the unsupported debug delayed-release
profile refuse. No configuration is changed to obtain a passing path.

The actual private allocator reserves one `LSF_DEVICE_CORE_PRIVATE` child of
that descriptor from the same original infrastructure bank before assigning
`dev->p`. It uses actual `sizeof(struct device_private)`, the original actor and
constructor fence, and the original PCI/descriptor generations. An address only
locates a prior whole birth. Foreign/interior/stale state cannot establish an
owner or fall back to the heap. All original list/device/error initialization
remains; ordinary devices retain the unchanged normal allocation path.

Both original free points pass the actual device and its already-born metadata.
A private device with an outside child and a normal device with a private child
both poison and retain; neither can reach normal free or retire a foreign birth.
Both genuinely outside values preserve the original free. The constructor
failure path keeps its original free/null/put ordering. Final release retains
original devres, DMA/override cleanup and PCI callbacks before the metadata
return. No private lock spans those callbacks. Original `kobject_cleanup` remains
byte-exact for normal objects. Only the same live selected birth dispatches a
private complete copy, whose added final notification follows the original type
release, name cleanup and actual parent put. Unregistered objects preserve the
original branch that omits an unnecessary parent put.

The existing firmware dispatch is gated until that tail is complete. It then
reserves and dispatches the same one original continuation; final companion put,
descriptor finish and PCI return retain their prior ordering. Constructor-held
cleanup additionally waits for original mutex unlock. Missing expected release,
unfinished child, stale/double callbacks or uncertainty poison and retain. A
logical view return never frees/refunds the original NodeFixed backing.
