# Retained attempt witnesses

This is a diagnostic subset: **29 published original files, 4,142,406 bytes**, copied without changing their bytes. The [manifest](manifest.json) records each original Windows/container path, size and SHA-256, verifies the copies, and records that the originals remained unchanged. It separately records the original empty smoke03 console log as a `not-published-empty-witness`, including its zero-byte size and SHA-256. The manifest and this README are generated descriptions.

These files permit inspection of the failed collection attempts, their final native collector and cleanup witnesses, the bounded export checks, and the later successful smoke. They are **not a complete replayable Phase 1 archive**. Referenced binaries, source trees, other per-owner raw files and large allocation streams/exports were retained in separate local evidence roots at publication; continued local availability is not promised; generated workload data was removed as recorded by its cleanup receipts. The full measured publication is separate.

Each failed-attempt directory contains the original `failure.json`, `backend-builds.json`, final `last-collector.json` and `last-cleanup.json`, as well as its suite. Full source hashes and actual ownership receipts remain in those files. The failed exports were not silently replaced by later successes. The [original console logs](notes/) also retain the outer `artifact-file-bound` failures; after the coexistence failure, retaining the oversized expanded file caused that subsequent ordinary inventory rejection.

The [allocation-size inspection](notes/issue108-allocation-bound-inspect.json.raw) and [coexistence inspection](notes/issue108-coexistence-smoke02.json) are retained diagnostic observations, not benchmark aggregates. The allocation inspection keeps its original UTF-8 BOM and is published as `.json.raw` to preserve every byte. The coexistence inspection records a 473,689,685-byte expanded peak file and a partial 5,098,471-byte gzip. The failed root occupied 1,073,732,184 bytes; excluding only the expanded file leaves 600,042,499 retained bytes.

Three bounded diagnostics explain the subsequent protocol changes without adding workload samples:

- The [export preflight](export-preflight-01/receipt.json) re-exported an existing N4 trace under a declared 512 MiB limit: 469,170,020 expanded bytes, 36,375 rows, 256,522 allocation weight, successful helper exit/reap, and zero new workloads. This justified the finite expanded-file allowance.
- The [first selected-attribution check](notes/issue108-selected-preflight-failed-01.json) failed with `unbound-helper-receipt`. The corrected [selected-attribution check](notes/issue108-selected-preflight-02.json) used the same retained N4 control owner, reported all four frame identities and zero unresolved allocations, and preserved its failed source suite. Both explicitly remain nonqualifying diagnostics; neither reran the workload.
- The [scratch preflight](scratch-preflight-01/receipt.json) compressed a copy of the existing 473,689,685-byte export into 7,110,251 bytes with a separate 512 MiB temporary-file allowance and a 16 MiB retained budget. It records the dirty diagnostic harness, verifies the original unchanged, and reports zero workloads. This tested the guard; it was not a clean benchmark run.

The later clean smoke used the declared single active 512 MiB expanded-file scratch allowance while preserving the 1 GiB retained evidence limit, ordinary 256 MiB retained-file limit, N4 profile population, and complete initial/reopen pairs. Historical failed receipts keep their original plans and source identities. Copying this appendix performed no workload or semantic/profile replay.
