# Call a capsule from your application

Use an LSF client SDK to call a capsule from Rust, TypeScript, Go, C, Java or C#.
In this tutorial, run one example in your chosen language. It calls HTTP and
storage capsules, handles an application error, cancels a request and checks
whether a configuration change succeeded.

The example starts its own temporary node and stops it when finished. It does
not change the node from [your first tutorial](../start/first-node.md).
Client programs run outside capsules. To write the code that runs inside a
capsule, use the [capsule authoring guide](../component-development/guest-sdk.md).

## 1. Prepare the example

Use the Linux source checkout and Python environment from the first-node guide.
Run the Bash blocks in one terminal, from the repository root. The current
native clients connect to a node on the same machine; this example uses numeric
loopback addresses. Browser applications use the separate
[application HTTP interface](../security/browser-boundary.md).

Install the tools for your chosen client language from the
[toolchain setup](../development/toolchain.md). Rust, `wit-bindgen` and Zig are
also needed to build the example capsules that the client calls.

```bash
set -euo pipefail
umask 077
export CARGO_TARGET_DIR="$PWD/target"
mkdir -p "$CARGO_TARGET_DIR"
CLIENT_DEMO=$(mktemp -d "$CARGO_TARGET_DIR/client-demo.XXXXXXXX")
cargo build --locked -p latent -p latentd
```

The new directory keeps this attempt's files separate from earlier attempts.
The first build can take several minutes.

## 3. Prepare the capsules and temporary node inputs

```bash
python3 tools/build_guest_capsules.py --output "$CLIENT_DEMO/guests"
LSF_GUEST_CAPSULES="$CLIENT_DEMO/guests" \
LSF_PHASE3_WORKFLOW_FIXTURE_ROOT="$CLIENT_DEMO/inputs" \
  cargo test --locked -p latentd --test phase3_workflow_fixture -- \
    export_signed_provider_workflow_fixtures --exact --ignored --nocapture
```

Expect `1 passed; 0 failed`. This prepares signed example packages and the
temporary node's trust settings. Run the next step soon afterward because the
demonstration signatures expire. These credentials are for this temporary
example; use [package delivery](deliver-and-recover-a-capsule.md) when configuring
your own installed node.

## 4. Run your client

Define this helper once. It starts the temporary node, runs the selected client
and saves the result:

```bash
run_client() {
  local language=$1
  shift
  python3 tools/run_sdk_provider_workflow.py \
    --cli "$CARGO_TARGET_DIR/debug/latent" --node "$CARGO_TARGET_DIR/debug/latentd" \
    --fixture-root "$CLIENT_DEMO/inputs" --language "$language" \
    -- "$@" > "$CLIENT_DEMO/result.json"
}
```

Show what happened:

```bash
python3 - "$CLIENT_DEMO/result.json" <<'PY'
import json, sys
with open(sys.argv[1], encoding="utf-8") as source:
    result = json.load(source)
checks = result["participant"]["assertions"]
print("Client language:", result["language"])
print("HTTP capsule succeeded:", checks["httpGuest"])
print("Storage capsule succeeded:", checks["blobGuest"])
print("Cancellation completed:", checks["explicitCancellation"])
print("Configuration change recovered:", checks["mutationReceipt"])
print("Node stopped cleanly:", result["nodeShutdown"]["record"]["clean"])
PY
```

Expect your chosen language followed by five `True` results. The example also
tries intentional failures, such as a wrong credential and an application error.
Those cases are part of the demonstration. A command that exits with an error
has not completed the walkthrough.

## Invoke an admitted guest

Now follow the code behind the example. Choose a language tab below; the source
link opens the complete program with its imports and setup.

<CodeExample example="client/provider-invoke" region="invoke" />

The client sends the target capsule, function arguments, a time/resource budget
and an activation ID. The HTTP capsule makes its permitted request through the
node. The storage capsule writes and reads four bytes. Provider credentials stay
with the node; the client does not need them.

A successful call, an error declared by the capsule, and a platform failure are
different outcomes. Handle each explicitly. Keep the activation ID if the reply
is lost so that you can ask about the original call.

## Cancel the wait, then inspect the original identity

## Finish or troubleshoot

The runner stops its temporary node and local HTTP server automatically. Your
builds and result remain under the directory printed by `printf '%s\n' "$CLIENT_DEMO"`.
You can remove that directory when you no longer need it.

| What you see | What to do |
| --- | --- |
| Missing compiler, generator or dependency | Revisit the setup link for your selected language and the common capsule toolchain |
| Expired demonstration signature | Start again at step 1 with a fresh demo directory |
| Connection or authentication failure | Use the runner's temporary configuration and keep its credential file private |
| An example command exits with an error | Keep its diagnostic and result files; start the next attempt in a fresh demo directory |

Continue with [provider failure and recovery](../how-to/exercise-provider-failure-and-recovery.md)
or [policy reconciliation](../how-to/reconcile-a-policy-change.md).
For detailed limits and language-specific ownership rules, see the
[shared client API reference](../../sdk/profile/README.md).
