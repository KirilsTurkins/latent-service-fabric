# Invoke, cancel and recover with a client SDK

Use your language's client to invoke an authorized guest, retain its activation
identity, distinguish application and platform failures, cancel explicitly and
recover a management operation. The same scenario runs in Rust, TypeScript,
Go, C, Java and C# against a separate authenticated node.

This is the **development, Linux x86-64, numeric-loopback HTTP/2 + Protobuf**
client profile. It does not add a public node listener or remote TLS transport.
These programs run outside the guest. The [Rust/C guest bindings](../component-development/guest-sdk.md)
and the [browser application boundary](../testing/sdk-browser-application.md)
serve different purposes: browsers use the approved application HTTP route and
never receive the node's management credential.

## Before you start

Use a clean checkout of the development source identified by this page's
**Exact documentation source** link. Install the repository's
[pinned toolchain](../development/toolchain.md) on Linux, including Python 3.13.5.
Run commands from the repository root under `umask 077`. Choose a private,
disposable working directory and keep node storage separate from client inputs.
The [first-node and delivery guide](deliver-and-recover-a-capsule.md) explains
authentication, readiness, signing, publication and deployment.

For this learning scenario the existing harness performs that setup, then starts
the chosen native participant. It supplies only the explicit client credential
path, loopback endpoint and admitted targets. Provider credentials remain with
the node. Fixture credentials are disposable public test inputs in protected
files; they are not production defaults. Do not print the participant input or
copy its credential into source, an environment variable, a URL or a browser.

## Invoke an admitted guest

The controlled node admits the maintained HTTP, immutable-blob and callee guests
under an explicit test policy. The client sends a supported WIT-value frame,
finite budgets and a caller-known identity such as `rust-http`. It does not
contact the provider using provider credentials. HTTP returns the encoded
unsigned value `2201`; the blob round trip returns `4` in this fixture.

<CodeExample example="client/provider-invoke" region="invoke" />

The **complete source** link includes imports, request construction, private
configuration loading, failure checks and shutdown. A displayed region is part
of that executable scenario, not a standalone program. Identity prefixes and
temporary policies belong to one disposable run; avoid reusing them against an
unrelated node.

Inspect success, declared application error and platform failure separately.
The callee's `fail` function returns its declared error; `spin` with a deliberately
small fuel budget produces a platform failure. Wrong tenant and wrong credential
are rejected before guest execution. A transport failure can leave execution
uncertain even when the local exception is definite.

Never coerce a wire `u64` through a JavaScript `number` or a signed narrowing
conversion. TypeScript uses `bigint` and decimal strings; Java uses its documented
lossless unsigned representation; C uses checked `uint64_t` fields. An absent
activation ID requests assignment; a present empty ID is invalid. Preserve
presence for zero-valued generations, deadlines and optional acknowledgements.

## Cancel the wait, then inspect the original identity

The fixture first holds an actual authorized upstream request. Its private
`started` marker is evidence that physical provider work began; it is not an
application API. The participant interrupts its own wait and then uses a live
client/context to cancel or inspect the original activation.

<CodeExample example="client/provider-cancel" region="cancel" />

| Language | Local interruption and retained ownership |
| --- | --- |
| Rust | Dropping the pending future ends local ownership. Use `Cancel`/`GetActivation` with the original ID; `Drop` alone does not prove guest cleanup. |
| TypeScript | `AbortSignal` stops the local wait. Recovery uses a live signal and original ID; `shutdown()` drains the client's shared transport owner. |
| Go | A cancelled `context.Context` cannot be reused for recovery. Use a live parent/bounded context, then `Close()` and inspect reaped ownership. |
| C | A local call handle identifies a callback operation, not the activation. Copy retained requests, copy callback results you need later, release call handles and stop/drain before destruction. Callbacks can run inline. |
| Java | Future cancellation is local and can complete exceptionally. A live observer retains the original ID; closing the owned channel/executor is explicit. |
| C# | A cancelled token cannot establish server cancellation. Use a live observer token, await each `ValueTask` once and await `DisposeAsync()` for finite shutdown. |

`accepted`, `already-terminal` and `not-found` are different successful Cancel
dispositions. None is a transport exception. `accepted` acknowledges the request,
not physical cleanup. Poll retained status under a finite deadline, and use the
provider's closure observation in this fixture. Bounded retention means later
`not-found` is not proof that an activation never executed.

The normal scenario uses the node's five-second RPC ceiling. Held work uses
three seconds, while the deliberate deadline case uses 500 milliseconds under
one original absolute deadline. Do not reset that deadline at a queue, pool or
RPC boundary. There is no automatic Invoke retry after a lost response.

## Inspect pages and reconcile a mutation

The shared management profile reads policies and redacted provider descriptors
with page size one, follows the exact continuation token and checks the catalog
generation. Treat page tokens as opaque. The participant creates an empty policy
with **expected generation zero** and a caller-known operation ID; that policy
grants no execution authority.

<CodeExample example="client/provider-management" region="management" />

Keep the original request and operation ID. After an uncertain response, lookup
uses that ID; an absent receipt remains unknown. The harness separately tests an
explicit replay of identical content and rejects a changed request or stale
precondition. This demonstration is not a universal automatic retry rule.
The current policy RPC has no audit acknowledgement: preserve its absence.
Do not manufacture an acknowledgement from an audit sequence or operation ID.

## Run against a separate real node

Follow [the guest SDK build and fixture export](../component-development/guest-sdk.md)
and [the native provider harness](../testing/sdk-provider-workflow.md) to build
the paired CLI/node and export fresh signed HTTP/blob/callee inputs. Export
immediately before execution; expired evidence must be regenerated, not edited.
The fixture root and the selected participant executable must be absolute paths.

Build the native setup tools and guests, then create fresh signed inputs with
the existing exporter. The temporary parent belongs to this walkthrough alone.

```bash
set -euo pipefail
umask 077
export CARGO_TARGET_DIR="$PWD/target"
cargo build --locked -p latent -p latentd
python3 tools/build_guest_capsules.py --output "$CARGO_TARGET_DIR/guest-capsules"
PRIVATE_RUN=$(mktemp -d "${TMPDIR:-/tmp}/lsf-client-guide.XXXXXXXX")
FIXTURE_ROOT="$PRIVATE_RUN/inputs"
LSF_GUEST_CAPSULES="$CARGO_TARGET_DIR/guest-capsules" \
LSF_PHASE3_WORKFLOW_FIXTURE_ROOT="$FIXTURE_ROOT" \
  cargo test --locked -p latentd --test phase3_workflow_fixture \
    export_signed_provider_workflow_fixtures -- --exact --ignored --nocapture --test-threads=1
test -f "$FIXTURE_ROOT/fixture.json"
```

Expected: the one named exporter runs and creates the new fixture inventory.
Do not continue after zero matching tests, a failed exporter or missing output.
Then, for example, after the Rust participant build:

```bash
umask 077
python3 tools/run_sdk_provider_workflow.py \
  --cli "$PWD/target/debug/latent" --node "$PWD/target/debug/latentd" \
  --fixture-root "$FIXTURE_ROOT" --language rust \
  -- "$PWD/target/debug/examples/provider_workflow" \
  > "$PRIVATE_RUN/rust.json"
```

`FIXTURE_ROOT` is the newly exported directory and `PRIVATE_RUN` is your private
result directory, created before the command. For another language, keep the
same owner and choose its actual participant command:

| `--language` | Command after `--` |
| --- | --- |
| `typescript` | absolute Node executable, then the absolute `sdk/typescript-client/tests/provider-workflow.mjs` path |
| `go` | absolute `target/go-provider-workflow` binary |
| `c` | absolute `target/c-sdk/provider-workflow` binary |
| `java` | absolute Java executable, `-jar`, absolute `sdk/java-client/build/latent-java-client.jar` |
| `dotnet` | absolute .NET executable, then the participant DLL path printed by your build |

The runner appends its protected `--config` argument. It checks actual participant
and node retirement, original activation/operation identities and four started
upstream requests whose sockets physically close. Expected output is one bounded
JSON receipt with `passed: true` and 18 participant assertions. Inspect its schema
using the [receipt contract](../testing/sdk-provider-workflow.md#required-result-and-independent-checks).
An empty test selection, partial language matrix or unreaped process is failure.

## Diagnose and clean up

| Observation | Next action |
| --- | --- |
| Connection refused or connect deadline | Verify the explicit loopback endpoint and authenticated node readiness. No execution is implied by an unsuccessful local connection. |
| Unauthenticated / wrong tenant | Recheck the protected client credential and tenant against the node configuration. Never print the credential to debug it. |
| Permission denied before publication | Inspect fresh publisher/builder policy and signed input identities. Local verification is not a runtime grant. |
| Declared error | Inspect the application contract's error variant; it is an observed application result. |
| Platform budget failure | Inspect the exact budget and current status. Keep the bounded failure case; do not silently raise node limits. |
| Lost response, size limit or local cancellation | Retain the activation ID and query status using a live recovery context. Do not invoke again to discover the old outcome. |
| Stale management precondition | Reconcile the original operation, then inspect current catalog state before deciding on a new operation. |
| Client cannot drain | Treat the run as failed, retain redacted diagnostics and the owner state, and let the finite harness cleanup run. |

The harness owns and removes its temporary node/client directories and joins its
process groups. Keep compact result receipts; remove only your explicitly chosen
fixture/build directories after verifying no owner is using them. Never remove a
persistent server's catalog as walkthrough cleanup.
