# Captured TypeScript compiler refusal qualification

This bounded programme supplies the specific negative evidence required by
#685. It complements the successful public/private, resource, generated-source
and three-stage watch components; it does not rerun or relabel those receipts.

Five ordinary outside local npm packages use normal add, native lock, resolve
and exact review commands. Each selected source is captured before its original
directory is removed. The unchanged ordinary build CLI then consumes that
reviewed closure under its existing network-denied compiler namespace.

Three cases must fail at the actual maintained bundler before componentization:
reachable dynamic `import`, reachable `globalThis.eval`, and a selected `.node`
addon. Two cases must pass bundling and reach actual component snapshot creation:
a module initializer calling `Date.now()` and one calling `Math.random()`. The
existing guarded intrinsics must reject each observation during that real
snapshot. A modeled JavaScript facade or an unrelated typecheck failure cannot
supply this evidence.

The qualifier requires the exact expected compiler stage and closed diagnostic,
successful preceding commands, a completed owned process and no successful
component or package. It rechecks the accepted source, lock and SDK, all recipe
materials, the pinned compiler installation and the supplied native tool bytes.
Limits remain 300 seconds per attempted build, 1,800 seconds overall and 4 MiB of
captured command diagnostics, with the original process ownership/cleanup bound.
No build, invocation, runtime authority or global timeout is widened.

Run after the normal captured dependency qualification:

```console
python3 tools/qualify_typescript_dependency_refusals.py --tools /owned/typescript-tools --contracts-tool /owned/native-binaries/examples-capsule_contracts --packager /owned/native-binaries/examples-package --output /owned/dependency-refusals
```

The maintained TypeScript job retains every previous command, artifact and its
75-minute bound, adding only the focused evidence controls and this programme.
Public receipts contain closed case/stage outcomes and captured identity rows;
raw compiler streams, private paths, credentials and signing keys are not added
to uploads. A generic setup error, timeout, unknown result or compiler advance
past the expected refusal fails qualification. Failed observation/reporting
never replaces the original failure.

The Python tests validate evidence admission and fixture/CLI boundaries. Only
the hosted programme establishes actual compiler/snapshot refusal. No successful
component, signed runtime result, async export, complete JavaScript runtime,
Fetch implementation or whole-ticket closure is inferred from these negatives.
