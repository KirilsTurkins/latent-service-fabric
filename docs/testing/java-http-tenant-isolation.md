# Java HTTP: same-node tenant programme

This optional controller reuses the single freshly compiled ordinary
`java-http-phases` application. It does not change the application, published
Webb/HttpRequest libraries, compiler recipe, default client settings, original
phase programme, provider limits or native production tuple. The selected Java phase campaign now runs it after the original sixteen
phase invocations. Signed tenant component execution remains pending.

The maintained neutral-packaging signer first validates the actual normal build
observation. Its new packaging-only observation retains the original source,
component, build type, compiler parameters and compiler materials, and names the
original observation and neutral derivation explicitly. The two tenant-local
publications select the same component digest and original exported contract;
they receive separate deployment identities and grants. The signing fixture is
public demo trust, not an authenticated production publisher.

One node and its original single execution cell install two normal HTTP
providers. Each installation has its own tenant, provider ID, configuration
digest, private credential directory and independently generated authorization
value. HTTP is never a scalar alias. Only the two existing clock providers and
activation runtime use their maintained bounded scalar aliases. The combined
eight descriptors remain below the original fourteen-descriptor ceiling, with
unchanged global and per-installation limits.

The finite twelve-outcome programme requires:

- Foreign invocation without its own grants is rejected before guest fuel or
  HTTP contact; an examples operator token cannot operate the foreign profile.
- Both ordinary published clients succeed independently for both tenants. Every
  successful response must begin with the original fixture's fresh invocation
  counter `1`, preserving actual static-state checks on the reused cell.
- The first tenant's real pending-headers read timeout and accepted root
  cancellation each retire physical owners; the other tenant succeeds afterward.
- The foreign tenant's request to the first tenant's ungranted origin makes zero
  wire contacts. The unchanged fixture wraps that refused Java IOException in an
  uncaught IllegalStateException, so the expected invocation result is a guest
  trap. This is distinct from a pre-guest grant denial or a provider timeout.
- Fresh calls succeed after the refusal and cancellation, with exactly five
  authenticated contacts per tenant and no mutations or secondary-origin calls.

Per-case invocation results, pending/cancellation witnesses and zero-owner
observations remain separate bounded files. Actual final node shutdown, peer
aggregates and before/after native/component identities are written before the
compact summary. Cleanup preserves an active primary exception and reports only
closed owner kinds if additional cleanup also fails; cleanup failure by itself
still fails the programme. No credentials or private configuration payloads are
included in public records.

Eight focused Python controls exercise configuration preservation, independent
credential scopes, complete descriptor validation before policy writes, exact
neutral signing ancestry, deployment isolation, strict result classification,
and cleanup identity. These are controller/source controls. Actual signed
same-node HTTP behavior, the default phase programme and public transport SPI
remain separate gates for #688/#741. This branch alone closes neither issue.
