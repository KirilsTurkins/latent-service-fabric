# Standard Fetch conformance campaign

This signed component campaign extends the default Fetch profile's real HTTP
coverage for [#691](https://github.com/KirilsTurkins/latent-service-fabric/issues/691).
It builds one new ordinary application through the normal maintained compiler,
packages/signs it and uses enforced node admission. The published Ky/Wretch
and outside-package programme remains a separate unchanged qualification.

The25 initial cases cover parsed200/404/500 responses, independent cloned and
used bodies, all seven methods, UTF-8 payload bytes and headers, already-aborted
signals, reserved credential headers, used requests, buffered native readers,
reader cancellation, GET-body refusal, malformed JSON/framing, truncation,
oversized bodies, unsupported encoding, separately authorized redirects,
denied destinations without contact and an uncertain POST without replay.

root return with accepted work. A generation-bound real peer gate is required
and released after150ms. A result before release fails the drain observation.

real active cell and provider before termination, then require known distinct
terminal codes and physical retirement. A fresh activation follows.

and operator configuration allow two outbound requests so a followed redirect

outbound accounting, including zero-contact refusals. The peer must observe
exactly28 requests, one committed mutation and one secondary redirect request
