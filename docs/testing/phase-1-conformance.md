# Bounded Phase 1 conformance

The selected deterministic profile exercises the real standalone Linux node,
operator CLI, durable catalogs and Wasmtime guests. It produces a versioned
report and raw diagnostics. Passing this profile does not complete
[gate #16](https://github.com/KirilsTurkins/latent-service-fabric/issues/16)
or the Phase 1 epic.

## Run and inspect

From a checkout with the [pinned toolchain](../development/toolchain.md):

```sh
tools/validate_contracts.sh
```

The contracts gate builds the required echo, generic and capabilities fixtures,
runs their existing owner suites, builds `latent` and `latentd`, then runs the
bounded profile. With those fixtures and binaries already built:

```sh
python3 tools/run_phase1_conformance.py
```

Each run creates a fresh `target/phase1-conformance/run-*` directory. Use
`--output PATH` for an explicitly new or empty directory and `--target-root PATH`
for a different Cargo target directory. Missing fixtures, failed compilation,
failed child assertions, absent reports and exceeded watchdogs are failures.
No case is silently skipped because its required toolchain is unavailable.

`conformance.json` uses `latent.phase1.conformance.v1`. The validator checks the
fixed [case manifest](../../benchmarks/phase1/cases.json), required case verdicts,
work totals, process identities, cleanup, bounded artifact paths and hashes.
The runner also checks reported input identities against the binaries, fixtures
and Cargo lockfile actually used. Source commit/tree and dirty state are
recorded. `config_sha256` identifies canonical JSON of the sanitized public
configuration; no credential-derived config hash is retained. A dirty local run is not evidence for an unmodified commit.

CI retains reports and diagnostics for 14 days in
`phase-1-bounded-conformance-<commit>`, including failures. A failure before
the profile starts may have only the contracts job log. No performance baseline
is generated by this command.

## Work limits and ownership

| Resource | Profile bound |
| --- | --- |
| Attempted Invoke operations | 64 aggregate; rejected and malformed attempts also count |
| CLI/direct-adapter/RPC commands | 256 aggregate; process allocation 224, adapter allocation 32 |
| Driver Invoke allocations | Process 48, adapter 16; no automatic invocation retries |
| Standalone compositions | One adapter composition, then one CLI-owned node; sequential |
| CLI payloads | Small fixtures, at most 4 KiB per input |
| Driver log / report | 4 MiB each; product child pipes have separate smaller bounds |
| Execution watchdog | 120 seconds after test compilation; adapter 50 seconds, process 65 seconds |
| Test compilation | Separate 600-second bound per target |

The cap covers this selected profile. Existing workspace and component owner
suites run separately; their aggregate execution count is not represented as 64.

`latent-testkit::process::OwnedProcess` retains each child and capped asynchronous
pipe readers. Explicit wait/termination reaps the child and joins readers. Drop
requests termination and aborts readers as a fallback; dropping an owner is not
a successful cleanup receipt. The outer Linux runner also bounds the disposable
driver process group so a failed test cannot leave its node running indefinitely.

Child resource observations bind the retained PID to its kernel start-time
identity before and after capture. They read that child's `/proc` entries and
intersect socket inodes owned by its descriptors with its network namespace's
TCP tables. Namespace-wide sockets and the test runner's resources are not
attributed to the node. All task child lists are bounded; missing data, unstable
identity or exhausted probe bounds fail the selected profile.

Samples cover empty readiness, a small dormant catalog before guest preparation,
warmup and idle state after mixed outcomes. OS and inventory reads occupy an
observation window; they are not an atomic kernel/runtime snapshot. Raw RSS is
recorded without interpreting a short run as a reclamation plateau. No OS timer
registration counter is invented.

Final cleanup uses the actual product `ShutdownReport`, zero transient owner
counters, telemetry flush, epoch-helper join, successful process exit and reader
joins. Conservatively quarantined cells are recorded separately; a quarantine is
not a live activation or leaked store.

The reusable `BorrowedBackendHarness` counts calls through a supplied real
activation manager and exposes its supplied execution backend.
`InvocationConformanceSuite` retains at most eight small typed outcome cases;
`ScopedNodeHarness` delegates start/status/cancel to the actual lifecycle owner
under one authenticated fixture principal. `ObservedInvariantProbe` reads the
actual inventory reporter and bounded telemetry sink. Its legacy idle-scaling
method requires a supplied measured latency source and otherwise returns an
explicit error, rather than fabricating a p99 value.

## Evidence coverage

The fixed cases cover small dormant catalogs, fresh guest stores, success/domain
error/trap distinctions, deadline, explicit cancellation, malformed input,
memory/log limits, current activation capabilities, tenant-scoped observations,
healthy recovery and owned shutdown. Additional bounded cases hold an activation
across a policy revision update and fill two active cells plus two queued owners
across tenants before checking acceptance rejection and recovery. Two tenant-correct component namespaces
use the same service name to exercise tenant separation.

Eight pairs compare a listener-independent invocation adapter with actual
loopback RPC through the same production node manager/backend: echo success,
declared error, malformed input, expired absolute deadline, zero memory, zero
fuel, a missing route and a foreign tenant. Typed results, receipt pins,
deterministic consumption fields and retained terminal status are checked.
Activation/trace identities, selected fixed-pool cell identity and wall-clock
measurements can differ between distinct calls. This selected comparison does
not establish complete backend/context/tracing or queue fairness equivalence.

Existing owning suites remain necessary: the scheduler tests tenant fairness and
bounded queues; activation lifecycle tests pinning, races and terminal retention;
wire tests ingress identity, deadlines and management boundaries; Wasmtime tests
canonical values, capabilities and interruption; standalone tests durable
restart and running/queued shutdown. The CLI workflows include publication,
pagination, source-file removal before restart, cancellation and interrupted
response ambiguity. Their passing assertions do not substitute for unmeasured
scale or calibrated resource evidence.

## Full gate remains open

Every report retains `phase1_completion: incomplete`, even when
`deterministic_status: passed`. The following required heavy evidence is
`not_run` with reason `not-authorized-heavy-work`:

- dormant registrations at 100, 1,000, 10,000 and 100,000 releases/deployments;
- a mixed workload soak and matched RSS reclamation baseline;
- a calibrated initial Phase 1 benchmark baseline; and
- comparable Phase 0 performance deltas for the changed composition.

Full gate acceptance also requires reviewing coverage against every criterion
in #16, including broader end-to-end fairness/budget and context/tracing
equivalence beyond the selected pairs and finite queue cycle. The checked-in manifest
and report schema are test definitions, not measured benchmark results.
The retained August 30 Phase 0 evidence and authorization keep their original
scope and are not relabeled as Phase 1 measurements.
