# Source-owned TypeScript import runtime candidate

`spidermonkey-activation-promises-clocks-imports-v1` is an explicit compiler
candidate. Its project, captured npm selection, exact engine input and exact
source-built compiler splicer must agree. The ordinary synchronous selection
remains the default.

The candidate links SDK-owned Promise jobs, timer globals, Abort/Event
ownership and separately scoped clock globals before application modules.
Its compiler retains actual asynchronous WIT imports, returns real native
Promises and drives timer/import readiness through one activation-local set.
Typed result lifting finishes before canonical subtask drop and physical
result/capture retirement. Asynchronous cancellation retains the original
handle, stable buffers and owners while the host reports `BLOCKED`.

The source candidate now distinguishes canonical result ownership from subtask
retirement. Cancelling before typed lifting retains an actual returned outcome
until a compiler-generated walk drops its imported `own<resource>` handles
through their original canonical resource-drop imports. The walk follows only
active variants and checked list element ranges. It does not free string or
list backing allocations and makes no transitive heap-release claim. A terminal
cancellation with no returned outcome never reads the result buffer.

Normal typed returns and intentional WIT error returns transfer ownership only
after their complete value or error object has been constructed. An unexpected
partial lift, unsupported disposal mapping or failed/partial destructor leaves
the record quarantined with its original owners; cleanup cannot replay drops
or report a refund. The native prerequisite campaign and the finite canonical
OWN-result campaign below have now executed this path. Canonical resource
destruction alone does not certify physical provider close, native quota reuse,
production support or completion of the SDK ticket.

If a private carrier has resolved before cancellation retires its record, its
queued typed lift rejects with the original cancellation string. Private
duplicate lifts of any already retired identity also reject with that string;
they return no value and perform no drop or acknowledgement. Zero and future
identities retain the internal invalid-record diagnostic.

The compiler refuses an execution slot when the queued task's actual exit Promise has resolved before its turn. It waits for the original current-task Promise to settle, then reports `selected-runtime-task-exited-before-slot` before choosing another queue entry. An exited middle waiter cannot run or remain waiting for an unrelated live successor. A cancellation request alone does not trigger this refusal, release native owners or grant successful completion. The pinned generator comes from the [ComponentizeJS source lock](https://github.com/bytecodealliance/ComponentizeJS/blob/4b8d6eb465b5cded6b97c67aaf6fdaa8b62001e2/Cargo.lock); focused JavaScript controls cover exited-first and exited-middle ordering. These controls do not qualify emitted-component cancellation or physical cleanup.
