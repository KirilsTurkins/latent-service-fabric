# Source-owned TypeScript import runtime candidate

`spidermonkey-activation-promises-clocks-imports-v1` is an explicit compiler
candidate. Its project, captured npm selection, exact engine input and exact
source-built compiler splicer must agree. The ordinary synchronous selection
remains the default.

The candidate links SDK-owned Promise jobs, timer globals, Abort/Event
ownership and separately scoped clock globals before application modules.
Its compiler retains actual asynchronous WIT imports, returns real native
Promises and drives timer/import readiness through one activation-local set.
Typed result lifting finishes before canonical subtask drop and physical
result/capture retirement. Asynchronous cancellation retains the original
handle, stable buffers and owners while the host reports `BLOCKED`.

The source candidate now distinguishes canonical result ownership from subtask
retirement. Cancelling before typed lifting retains an actual returned outcome
until a compiler-generated walk drops its imported `own<resource>` handles
through their original canonical resource-drop imports. The walk follows only
active variants and checked list element ranges. It does not free string or
list backing allocations and makes no transitive heap-release claim. A terminal
cancellation with no returned outcome never reads the result buffer.

Normal typed returns and intentional WIT error returns transfer ownership only
after their complete value or error object has been constructed. An unexpected
partial lift, unsupported disposal mapping or failed/partial destructor leaves
the record quarantined with its original owners; cleanup cannot replay drops
or report a refund. The bounded native prerequisite campaign has built the changed compiler and
engine. Actual canonical component cancellation controls remain required. Canonical
resource destruction alone does not certify physical provider close, native
quota reuse, production support or completion of the SDK ticket.

The separate `typescript-owned-results.yml` programme builds one fresh normal
source splicer and engine and executes all 13 maintained Rust descriptor /
disposer tests and 13 real SpiderMonkey manager diagnostics. It retains all 11
borrow controls and adds cancellation through real JS `finally` and the
resolved-carrier/public-lift race. Six affected lifecycle C++ controls also run
with explicit opaque-JS headers and canonical/broker doubles, including immediate
handle-zero disposal and delayed/no-result retirement. Those references do not
execute JavaScript; delayed cases retain their original readiness-set owner. All 29 Python controls must pass without
skips using the normal pinned compiler parser. The actual Wasm32 diagnostic
measures the new Record size against the immutable pre-OWN header; it does
not reuse the historical borrow ABI claim.

This first programme authenticates one fixed completed low-level library,
restores only its original headers and supporting objects, and requires the
same normal library validator before building the changed compiler or engine.
It preserves the original receipts and source pins. It has no Mach fallback.
Checkout/setup and all stages share a 90-minute job bound; the programme also
subtracts setup time from its monotonic deadline. Splicer, Rust tests, engine
and C++ compile/link retain their narrower 900, 600, 1200 and shared 120-second
ceilings. Those maxima are not additive permissions to exceed the job bound.

The [native prerequisite receipt](../testing/typescript-owned-result-native-evidence.json)
records 29 Python controls, 13 Rust tests, 13 real SpiderMonkey manager cases and
six lifecycle references, all passed. Wasm32 Record size is 256 bytes against
the immutable 248-byte baseline (+8), with 8-byte alignment; manager size remains
112 bytes and the observer is 72 bytes. These are relative layout measurements.
The C++ broker and canonical intrinsics are explicit diagnostic doubles. Actual canonical OWN component disposal, resource
table reuse, signed execution, provider physical retirement and whole-cost
qualification remain unexecuted obligations after these prerequisites.

If a private carrier has resolved before cancellation retires its record, its
queued typed lift rejects with the original cancellation string. Private
duplicate lifts of any already retired identity also reject with that string;
they return no value and perform no drop or acknowledgement. Zero and future
identities retain the internal invalid-record diagnostic.

The engine requests the existing activation interface and both clock
interfaces. Recognition, compiler selection and reading a clock grant no
authority: each interface still needs ordinary installation, policy and grants.
Unsupported runtime modules, addons, process APIs and dynamic loading retain
concrete diagnostics.

Build observations bind the exact native SDK source, original upstream pins,
source derivations, compiler-tool bytes and build/transpile receipts. Their
qualification remains `unknown` and API support remains `not-evaluated`.
An operator-provided compiler input cannot certify runtime support.

The compiler refuses an execution slot when the queued task's actual exit Promise has resolved before its turn. It waits for the original current-task Promise to settle, then reports `selected-runtime-task-exited-before-slot` before choosing another queue entry. An exited middle waiter cannot run or remain waiting for an unrelated live successor. A cancellation request alone does not trigger this refusal, release native owners or grant successful completion. The pinned generator comes from the [ComponentizeJS source lock](https://github.com/bytecodealliance/ComponentizeJS/blob/4b8d6eb465b5cded6b97c67aaf6fdaa8b62001e2/Cargo.lock); focused JavaScript controls cover exited-first and exited-middle ordering. These controls do not qualify emitted-component cancellation or physical cleanup.

The maintained `tools/build_typescript_source_splicer.py` builder captures the
original ComponentizeJS archive, verifies the selected derivation preimages,
and uses its original locked Cargo workspace and upstream JCO componentization
and transpilation commands. Supply the unchanged compiler namespace produced
by `typescript_capsule.py install-tools` with `--tools`, and a fresh independent
directory with `--output`. It rechecks the original public WIT, Cargo lock,
derived sources and every captured compiler file after the build. The resulting
`splicer-input.json` binds the generated JS/Wasm bytes and successful command
receipts. The independent 20-minute source-splicer CI job executes this build;
its products remain compiler inputs until the signed runtime matrix passes.
The native engine builder accepts this completed build explicitly through
`--source-splicer-build`. It verifies the input and source/build/transpilation
receipts before and after compilation and binds `compilerSplicerInputDigest` in
the import engine envelope. This selection adds only the two internal import
bridge sources. The original native TextCodec definitions remain selected by
upstream CMake, with their source preimages and generated installation order
checked. The existing clock-engine build still runs before this additional
import-engine build; source compiler completion is a strict prerequisite.

The pinned SpiderMonkey derivation exports `ActivationPromiseHooks.h` through
its normal `js/src/moz.build` header list. The exact upstream build descriptor
is authenticated alongside the Promise implementation and object declaration;
an unreviewed descriptor fails before patching. A source rebuild needs this
export so the generated public include tree contains the native hook ABI.
Regenerate source-bound engine inputs after changing the derivation. The
[header export control](../testing/evidence/typescript-promise-header-export-2026-10-16.json)
confirms normal header generation and the changed-source rejection; it does
not establish a complete engine build or runtime qualification.
