# Finite Buffer qualification programme

The source-owned `node:buffer`/`buffer` profile has a separate eight-case signed
programme. Source controls are not a successful compiler or runtime result.
Until an owning campaign passes, typechecking, bundling, component execution,
signed admission and physical activation retirement remain unqualified here.

`tools/qualify_typescript_buffer.py` creates an ordinary captured greeting
project, replaces its public WIT and sources with the retained Buffer probe,
and runs the unchanged maintained TypeScript build and package path. The
compiler must complete its actual `typecheck`, `bundle` and `componentize`
commands. Both builtin aliases must select the single maintained module. The
normal build retains the actual Buffer-selection receipt as a package asset
and observation material, bound through package inputs and normal signing.
Unselected applications acquire no Buffer asset or declaration requirement.

The programme consumes an authenticated existing five-product native host via
`java_phase_native_products.verify_prepared`. It consumes the completed emitted
engine and source splicer through the unchanged normal Compiler validators.
The frozen engine was built in run40042939576, whose later native diagnostic
compile timed out. That whole producer remains failed, and its native controls
were not run. Completed engine construction is a compiler input, never Buffer
or native-control qualification. No engine or SpiderMonkey library rebuild is
needed for this pure JavaScript profile.

One normally packaged component is signed with the isolated demo-sign trust,
admitted through a normal standalone node and invoked eight times. Each
invocation must observe fresh module state, return its exact typed result and
report zero outbound requests, child calls, log bytes and effects. The unchanged
128MiB memory/120s activation limits still apply. The three explicit clock and
activation support bindings retain their original bounded owner profiles;
Buffer selection grants no I/O or provider permission.

| Case | Required actual observation |
| --- | --- |
| Aliases | Same namespace and Buffer constructor through both builtin names |
| Views and copy | Real ArrayBuffer sharing, independent copies and overlapping copy |
| UTF8 boundaries | Whole-codepoint writes, BOM, invalid bytes and lone surrogates |
| Finite codecs | Hex/base64 tails, low-byte coercion, ASCII, Latin1 and UTF16 |
| Integer ranges | Endian fixed/variable/BigInt operations and refusal without mutation |
| Fill/concat/compare | Aliased fill snapshot, bounded copies and zero-filled tail |
| Profile ceilings | 1MiB Buffer/4Mi-code-unit string limits and unsupported API refusal |
| Relative fixture | Repository-owned ordinary relative import only |

After every actual result the normal node observations must report no active
physical owners or invocation-cleanup slots. Deployment deletion and a clean
reaped node shutdown are also mandatory. This proves only the reported
activation population. It does not prove socket or returned typed-resource
disposal, cancellation acknowledgement, Duplex backpressure, destroy/unref
semantics, or an unchanged published npm client. The relative fixture is not
published-module evidence. Issue745 remains open for those separate gaps.
