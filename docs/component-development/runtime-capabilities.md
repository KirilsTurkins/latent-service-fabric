# Guest API and runtime capabilities

This versioned matrix records the maintained API surfaces at development `6c88d8b9fde61fa8b94b1bf05c20494933017f64`. It is separate from the optional package catalogue. [Machine-readable v1](../reference/guest-runtime-capabilities-v1.json) binds the source files for each row; resolution, build and admission never read it. Changing a dependency name cannot change API eligibility.

**Qualified finite programme** means only the linked original experiment passed. Every receipt retains its actual compiler, runtime, component and historical native identities. It does not claim a rebuilt current host or qualify the untested combinations of rows. **Implemented source** identifies source without general execution proof. **Proposed** means required implementation or qualification is still missing; mechanism tests and reference-runtime success do not make it supported.

Ordinary dependency declarations and runtime-profile selection are the primary workflow. Endpoint/credential configuration and reviewed explicit grants are still required. Recognition, source compilation and provider installation are separate observations. No selection here installs a provider or permission. In particular, typed HTTP method/path/header grants never authorize opaque stream traffic. See [dependency diagnostics](library-compatibility.md) and the [guest workflow](guest-sdk.md).

## Interpretation and updates

Limits above identify selected test/runtime profiles, not universal defaults or minimum library requirements. Execution budgets, admission charges, provider quotas, physical owners and static bounds remain distinct. Cancellation, handle disposal and a reaped caller cannot prove worker drain or external rollback. Root deadline and uncertain mutation remain failures with their original status.

Update this document and the JSON together when source or evidence changes. Retain old source-specific receipts, record new source identities, and keep incomplete API/lifecycle combinations visible. Package observations belong in the [versioned compatibility catalogue](../compatibility-catalogue/README.md); proposed ports belong to their implementation tickets. This matrix supplies no six-runtime completion certificate.
