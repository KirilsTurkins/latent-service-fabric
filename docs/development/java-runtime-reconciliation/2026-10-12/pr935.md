# Approved Java annotation processor reconciliation

PR #935 retains the useful source-processing stage from snapshot
`7f6fd0832b6b0af73b15889343ecdfb4142314c7` and reconciles it with the current
Java dependency, generator, activation, resource, server and client owners.
Issue #682's body and all comments were refreshed on 12 October 2026. The
generic generator delivered by #843 does not select annotation processors or
protect Java declarations produced by them.

The toolkit now captures explicitly named processor classes and their helper
JAR graph as executable build inputs. Passive capture and lock review start no
processor. Execution requires the exact source, recipe, compiler and sandbox
approval digest. The processor stage uses the maintained Linux namespace
boundary, a 60-second deadline, 256 MiB JVM heap and 16 MiB generated-source
limit. Its parent accepts only new UTF-8 Java sources. Pinned Javac parsing
checks declared and nested class ownership, including Unicode escapes, before
those sources enter the normal proc-disabled compilation. Processor API JARs
are compile-only inputs, and generated sources retain application origin and
checkpoint classification for a separately selected activation profile.

## Actual source and signed execution

The maintained `tools/qualify_java_annotation_processors.py` recipe creates a
new outside-checkout processor and transitive helper with uncatalogued developer
identities. It first proves the unapproved build fails at the exact approval
boundary, then executes the approved processor in its own contained workspace.
The processor proves the parent environment and parent-only sentinel are absent,
the original source is read-only, and the listening parent loopback peer receives
zero connections. This is the declared single-user build-host boundary; it is
not hardened hostile multitenant isolation.

The current local run used freshly built and frozen ordinary default native
products from source `89394cc3221d7c4e3073f102e3651b4d16347f75`, tree
`949af0b9f061a5da7a44f8d236ebcd44e42d553f`, Wasmtime 48.0.5 and
`lsf-host-abi-phase3-v5`. Actual Cargo artifact features were empty for all five
selected products. Completed product identities are not packaged-release
approval. The later predecessor merge changes only handoff and reviewed CI
contracts; the native evidence remains explicitly identified by its original
source head. Qualification source identities are recorded separately.

The approved stage produced `outside/generated/Message.java`. Current TeaVM
compiled it into a real component, which was signed using isolated synthetic
fixture trust. A fresh ordinary default node rejected the unsigned package and
the missing runtime grants before successful invocation. Three fresh calls
returned `Captured Ada`, the original empty-name declared error, and `Captured
Bob`. All core guest, cell, compiler, cancellation and quota owners retired;
shutdown joined physical workers and reported clean with no active or retained
provider owners. This pure component has no HTTP ingress, so the observer
requires the common core owners and does not require absent HTTP-only entries.
The original 256-record journal, 32 KiB/eight-operation queue, 64 MiB guest
memory and 120-second root deadline remain intact.

The actual parse-only negative controls reject original and nested class
collisions, platform namespaces, Unicode-escaped platform namespaces, generated
package/path mismatch and invalid source. Every case requires its exact fixed
reason and exit code, rather than counting an arbitrary JVM failure as evidence.
Earlier runs launched that standalone control from an invalid package path;
their six refusals are retained as invalid negative evidence. The production
stage already used the correct package path. The corrected final run repeats
all six controls, containment, build, signing and three node calls successfully.

The compact identities and results are in [pr935-evidence.json](pr935-evidence.json).
