# Private native observation after Root return

This is an uncompiled source implementation for #738. No new kernel, native
programme or VM has run. Normal installation is still Unsupported; every native
outcome, including an authenticated return observation, quarantines the entire
original one-MiB backing and connection. This is not a refund or production gate.

The additive source projection authenticates the actual #1398 whole factory,
collector and three layout preimages. It leaves all 294 historical kernel recipe
inputs unchanged and is not selected by their old producer. A future reviewed
producer must compile a new image; the old immutable image cannot qualify this
new API. Existing constructor qualification never mints the additional file.

One new explicit qualification constructor first reaches authentic bootstrap
READY, then mints one observation FD from that same protected original file.
The fixed ioctl is `_IO(0xb7,1)` (`0xb701`), argument zero, with a scalar c_int
descriptor return. It accepts no pointer, flags, credentials, cost or alternate
FD. Kernel full actor/READY/original typed birth checks precede allocation.
Only the existing constructor selection permits it; no production consumer is
selected. The private leaf additionally verifies the root-owned mode0600 device
and protected namespace. Those checks rely on the selected trusted kernel/device
contract; they do not attest a boot image or protect against hostile root.

The leaf crate alone uses a reviewed private unsafe ioctl implementation under
crate deny/scoped allow, matching the existing Wasmtime lint pattern. Workspace
and latent-streams unsafe forbids remain unchanged. Its sole public Unix entry
is mint(&File) to OwnedFd; unsupported Unix platforms return Unsupported and
non-Unix consumers do not link this Linux-only dependency. Rustix maps errno
before the custom extraction. Successful c_int descriptors, including zero, are
immediately adopted with no cast, fallible gap or raw descriptor escape. Getter
or NoArg wrappers are not substitutes for this scalar descriptor ABI.

The kernel uses get_unused_fd_flags, security-initialized
anon_inode_create_getfile with the original device inode, then publishes the
complete binding before fd_install LAST. There is no post-install file/actor
access. Allocation failure returns the unused FD reservation and observer refs,
marks only its own sticky failure, and leaves original Root eligibility intact.
It never disables security hooks or poisons the factory for observer failure.

One static slot and wait head live outside the bank and never reset or recycle.
They contain scalar birth identity, monotone observation phase and four
independently acquired mm/pid/cred/net references. They contain no Root, Request,
Task, Control, original File or page pointer. The original final VFS release,
private_data clearing, original Root terminal/IRQ/page guards and unpublication
remain unchanged. The collector captures scalar identity before its LAST Root
payload use and publishes only after actual bank free and all four original
actor puts. Closing the observer early cannot prevent Root collection; its own
actor puts happen outside the original locks.

The returned record is exactly 48 little-endian bytes:

| Offset | Field | Size |
| --- | --- | --- |
| 0 | magic 0x4c534652 | 4 |
| 4 | version 1 | 4 |
| 8 | returned phase 1 | 4 |
| 12 | error, zero | 4 |
| 16 | original owner slot 63 | 4 |
| 20 | original Root slot 1 | 4 |
| 24 | original owner generation 1 | 8 |
| 32 | original Root generation 2 | 8 |
| 40 | immutable successful-bootstrap expiry | 8 |

These are the current single-birth constructor identities, not caller-chosen
names or costs. Pending reads return EAGAIN. Poll registers only authenticated
files, then rechecks readiness; the static wait head outlives all wait entries.
The pinned poll machinery holds a File reference through wait-entry removal.
User copy happens after unlocking and uses only the fixed stack record.

Before mint entry, the native original Resource receives a fixed additional
4-KiB metadata owner from its existing quota. A compiled sizeof assertion bounds
that owner, wire, one pollfd and timespec within the reservation. Separate C
sizeof assertions bound the fixed slot/wait storage and retain the original
bootstrap ceiling. These assertions are source only until compilation. They do
not certify VFS/LSM/dentry/FD-table/RCU allocator costs; those remain unqualified.

The existing admitted blocking close worker sends CLOSE3 and drops the original
File before waiting on the separate observer. It uses one pollfd, at most sixteen
interrupt retries, and the original deadline narrowed to at most twenty seconds
and any earlier close-observation deadline. It does not extend bootstrap expiry
or create a Task, workqueue, queue, retry mint, reconnect or generic result API.
Only an exact fixed read before that deadline can report KernelRootReturned.
Short/error/stale/unknown/pending/timeout replies provide no return credit.

The observer File becomes a local affine owner and closes before the callback
returns, including unwind. Its metadata stays in the quarantined Resource even
after file close, conservatively covering uncertain VFS tails. The same existing
CloseBilling keeps worker, channel and result storage paid. All outcomes still
quarantine the original connection/backing, and the record/receipt is not an
affine refund token. The static slot itself survives Root, so the full current
reservation cannot be refunded as though all its metadata were deallocated.
There is no guessed split, reset or recovery from irreversible quarantine.

Four Python source controls check complete preimages/inverse preservation,
actual actor/mint guard operands, scalar layout and physical publication order.
Existing Rust codec/paid-owner controls gain finite new assertions without
removing cases; the leaf has one real descriptor ownership/refusal control.
Rust and C remain uncompiled/unexecuted. A later actual campaign must retain
original image/load/CPIO/VM caps and independently prove authentic read, genuine
Root return, paid observer lifetime and continued native quarantine. Full
allocation/cost closure, native refund, ordinary socket/TLS integration,
runtime/operator/adversarial qualification and whole #738 acceptance remain open.
