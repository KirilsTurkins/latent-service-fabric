# Separate early HTTP runtime collector

`tools/run_java_early_http_qualification.py` consumes the separately compiled
`forbidden-http-before-stage` capture documented in the
[compiler packet](pr970-early-http-compiler-evidence.json). It does not replace
the original post-stage forbidden HTTP fixture or establish that fixture's
rollback behavior.

The closed input selects one compiler source and exact report, component and
compiler-closure digests. The collector revalidates the complete source archive,
SDK closure, companion, original guest limits and early-call declaration. Fresh
ephemeral package signing and current authenticated publication remain distinct
from execution authority.

The four node sessions are publication, ordinary policy/deployment authority,
namespace creation and the early runtime. Runtime installs exactly the captured
publication's update/query/scan operations under its own service and companion
binding. Observed state and clock profiles supply proposals; ordinary CAS
mutations grant only state and clocks. No HTTP, deferred-intent, recovery or
restore authority is added. The protected native owner initializes its clock.
Trigger CAS finishes in the metadata session before runtime captures its current
control catalog transaction. Runtime startup does not mutate that catalog.

The actual command has `reject=false` and a positive delta. In the exact pinned
Java source, its declared `rejected` result can be returned at this position only
after receiving typed HTTP `permission-denied`; another platform failure traps.
The collector requires that declared result, its durable command identity and
retained bytes, identical replay and an unchanged absent business key. An actual
TCP listener reserves the captured loopback port 1 through physical node
retirement and must observe zero contacts. Existing strict-command and resource
limits remain unchanged.

All four original shutdown reports must show actual store/native physical
retirement and zero owners. Every native executable, collector file and capture
is checked again after execution. A failure retains its private root and leaves
all qualification fields false. The new source controls are not a native runtime
pass; actual execution remains required. Packaged distribution, independent
acceptance and original post-stage rollback qualification remain separate.
