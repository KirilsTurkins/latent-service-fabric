# Catalogue-free TypeScript default clients

This [#691](https://github.com/KirilsTurkins/latent-service-fabric/issues/691)
qualification tests the normal outer builder with optional catalogue/reference
material physically absent from its source root. Existing compiler-child
isolation is preserved. The finite signed result passed on the exact source below; the previously
qualified two outside identities and full phase/conformance programmes retain
their own exact source identities.

The stager retains the complete maintained recipe (110 distinct initial files,
111 after the selected phase manifest is captured), the selected import engine
input closure, activation/clock WIT and required v5/v7 host ABI manifests. Static
Python imports are followed recursively, including package initializers and
conditional imports. Only those Python files and explicitly enumerated recipe,
engine and manifest files are accepted. No docs, compatibility catalogue,
catalogue reader, tests, optional module metadata or checkout dependency tree
is copied. This does not replace a catalogue with another eligibility list.

The staged source has a bounded, exact inventory: at most 256 files, 1 MiB per
file and 16 MiB total. Regular single-link files are required; traversal,
symlinks, reparse points, extra data, removed engine/WIT/manifest inputs and
inventory mutations refuse before successful qualification. Rehashed extra
Python readers are also refused. The CLI starts from the fresh directory with
empty `PYTHONPATH` and no bytecode output. It uses the ordinary `build` entry,
normal namespace isolation and the same captured SDK/dependency graph. Its
inventory, actual recipe and selected engine/compiler inputs are verified
before and after construction.

One fresh application captures unmodified Ky 2.2.0, Wretch 3.0.9 and a new
outside-checkout private coordinate through the ordinary lock/resolve/review
path. The original private origin is removed. Its only client-source change
from the qualified phase fixture is the private import coordinate. No injected
fetch, package-name backend branch, new engine or native build is introduced.
The fixed 8f operational HTTP native products and original source-bound import
engine/splicer are authenticated separately; their receipts are not relabelled
as current native compilation.

Three signed/admitted activations must parse real JSON through Ky, Wretch and
the private transitive default client. The existing uniform two-billion fuel
phase profile and qualified 64-task/64-queue/256-native-owner client profile
remain unchanged. Each activation requires the exact typed result, one actual
outbound, no child/effect authority, a reaped CLI and physical provider/runtime
retirement before the next call. The controlled peer must observe exactly three
authorized primary-origin requests, no cookie/proxy credentials or mutations,
and a clean node stop. This is a focused catalogue-absence smoke, not another
31-case conformance replay or whole SDK/runtime/kernel qualification.

Run the hosted `TypeScript catalogue-free normal HTTP build` workflow. It
installs only normal pinned public tools, downloads the two existing compiler
products and five fixed native products, then builds one new guest component.
Source tests and real peer controls alone do not count as signed success.
