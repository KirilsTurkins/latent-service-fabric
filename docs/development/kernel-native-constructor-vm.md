# Native Rust constructor and maintained-kernel join

This programme joins two previously separate prerequisites for #738:
the real Rust `StreamProvider::install_kernel_constructor_for_qualification`
caller and the already qualified constructor kernel. The ten original native
owner controls use real ordinary Linux test descriptors; the earlier kernel
programme uses its C wire probe. Neither result alone executes this new join.
Actual static Rust compilation passed, but the new C supervisor, combined image
size and VM outcome remain unqualified until the owning workflow passes.

The production implementation is unchanged. Normal installation still returns
Unsupported, host TLS remains unqualified, and the socket consumer remains
unselected. No stream connect, DNS request, guest socket, language runtime,
signed component or full standalone node is exercised by this programme.

The closed Rust example creates the existing broker, IoRuntime and provider pool
with their original limits. Its static loopback TCP configuration creates no
connection and grants no application authority. It first verifies that normal
installation is refused without changing the original pool snapshot. The
qualification constructor then opens the exact protected device and uses the
original BEGIN/pending/WAIT protocol with its monotonic expiry. No transport,
allocator, descriptor path or completion assertion is injected into that caller.

The actual ready snapshot must retain one connection, the original maintenance
permit and at least the original one-MiB backing charge. A bounded `/proc/self/fd`
inspection observes exactly the protected device descriptor without disclosing
other paths. Normal provider retirement moves the existing NativeOwner into its
original bounded blocking cleanup. Its final snapshot requires that descriptor
to be absent, its extra close job to have returned, and its original connection,
maintenance permit and backing charge to remain quarantined. Native capacity is
not refunded. Process exit is not a live-node quota-reclamation certificate.

A tiny PID1 supervisor reuses the maintained probe's helpers and pure kernel-log
ABI reader. It mounts the finite temporary filesystem, executes the actual Rust
child once, checks real zero exit status, and waits for the genuine facility-zero,
nonfragmented kernel post-return record. It never echoes that record. The event
wait retains the original twenty-second overall bound, 4,096-byte records,
65,536 total bytes, 128 records and 128 interruptions. It checks expiry after
reads and before success. Failure, overrun, missing data or child failure cannot
qualify. The only host entry runs twelve pure C parser controls before all
mount/child/device/reboot work; the Rust example is never executed on the host.

The host independently requires the unique original kernel UART physical-return
marker and every ordered native/PID1 observation. Kernel delivery and userspace
UART order are checked independently: reading the printk ring does not fence
cross-CPU console delivery. Pending handoff/outside markers are retained when
actually present; they are not invented or required as a particular close race.
The shared physical-return observation proves only the existing original Root
bank/actor-reference return under that image's guards. It is not native refund,
full socket allocation closure or production stream accounting.

The fixed image input is the actual #1398 source
`0f1e453448bc10a7d2c60453ab69140283834182`, run40036590425,
job120697476339, artifact12538540188. The original 17,174,886-byte ZIP is pinned
by SHA256 `8d5fe3c3fce9ea944f8e11a3bc2a59101e284ba8a9404ac134c51efc18a96875`.
The strict reader requires its successful run/job/origin, all55 CRCs, exact raw
qualification/selection receipts, all294 unchanged kernel-producing materials,
original config, image and firmware identities. Unknown or expired products
refuse; there is no kernel rebuild or moving-reference fallback. The historical
three-boot result keeps its original attribution and is not replayed here.

The new programme builds only its ordinary source-matched Rust example and C
supervisor. It uses the installed pinned native Rust target and host GCC with
explicit static/non-PIE options; no new stdlib/sysroot is selected. Optimized
stripped output must pass the static ET_EXEC/no-interpreter/no-write-execute
grammar. The original PID1 C init retains its 2-MiB file limit and unchanged
validator. The new separate Rust child has an explicit fixed 3-MiB file partition;
its validator copies that grammar with only this file limit changed, under an
exact inverse source control. Both actual loaded spans, including BSS and gaps,
must additionally sum to at most the original 4-MiB image allowance. The child
partition is not a general limit knob or an increase to native provider capacity.
The original image helper and all294 kernel-producing inputs remain byte-identical.
If either executable or the aggregate does not fit, this candidate fails. The
fixed newc transformation preserves the
original console/proc/sys entries, replaces only init, and adds only the native
executable and temporary directory. The complete initramfs remains at most4MiB.

The first owning attempt stopped before compilation: resolving the rustc launcher
invoked rustup instead. The corrected launcher check observed the pinned rustc

then failed the earlier candidate's 2-MiB child read before C compilation or VM
execution. The third attempt retained the regular rejected ET_EXEC as forensic
data: 2,931,200 file bytes and 2,958,280 loaded-span bytes. It was not admitted or
executed. These remain failed attempts; their old limits and receipts are not
rewritten. The subsequent explicit child partition keeps its actual code and
standard library intact. Fit of the new supervisor and both aggregate bounds
still requires the actual owning result, rather than the older C init's size.

One fresh VM uses the unchanged two CPUs, 512MiB, isolated TCG, no external
network/disks and 180-second watchdog. Timeout is never success. The new source
recipe captures actual tools, source, compiler output, static images, raw UART
and the immutable kernel origin before/after execution. The ordinary compiler
and system implicit inputs are not fully attested; reproducibility and whole
native/GC/kernel costs are not established. No original native/kernel/runtime
baseline is rerun by this owning slice.
