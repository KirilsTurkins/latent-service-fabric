# Focused .NET reflection execution

The explicit reflection_replay selector in dotnet-guest.yml retrieves the fixed original03a qualification, native products and four companion packages. It authenticates all original receipts and source identities. Only the two explicit, default-off reflection probes differ in the current runner; projecting them out must exactly recover the original runner AST. No original normal qualification is rewritten or recreated.

The job captures an outside managed package, its literal trimming descriptor and embedded dynamic assembly, removes originals, builds with the maintained offline NativeAOT compiler, and normally packages, signs, admits and executes the component. All four reflected/dynamic/fresh cases and the original normal node controls must pass. Native Cargo products are not rebuilt. Compiler inputs and current fixture inputs retain their distinct source identities. Public artifacts include actual build selections, containment, provenance and node receipts. No JIT, general reflection, full ticket or production-builder trust claim is made.

The original four-case programme remains the default. Selecting `reflection_suite=boundaries` together with `reflection_replay=true` compiles the seven-case fixture through a staged, pinned compiler-source closure with no optional catalogue or reference data. The selected descriptor and actual build recipe remain bound. The node must complete all 27 normal calls plus seven reflection cases, including caught dynamic-method and byref-like invocation refusals, followed by supported fresh reflection; shutdown must be clean and physically reaped. The receipt distinguishes the original native compilation from this fresh application build. Source controls alone do not establish that hosted result.
